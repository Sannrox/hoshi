# Changelog

## Unreleased

### Changed

- TUI redesign ("Slate"): play opens on the bridge dashboard: alert callouts, a star map and an upcoming timeline (next 60 minutes) beside queues and fleets, under a navbar and a resource strip (stock / cap with a fill bar and hourly rate, energy in/out, heat load). Screens are grouped into six hubs (bridge, colony, fleet, trade with market, finance and KPIs, empire with incidents, records) opened with 1-6; a hub opens as a centred window over the dimmed bridge (full screen below 120x40) with tabs, a subtitle (planet, kind, queue or active research), a footer note and its actions. Tab walks screens in hub order, shift+tab goes back, esc returns to the bridge (x still cancels). Buildings use a table with level, Fe/Si/D cost (red above stock), time and a status chip, with the inspector beside it: level tag, properties, cost bars, a now/next/delta effect table and requirements. The status bar shows the breadcrumb and the keys for the current screen. The per-planet glance lines above each screen are gone; `[`/`]` changes the window subtitle and the table. Colours adapt to truecolor, 256 or 16 colours and honour `NO_COLOR`; high contrast drops fills for plain text.

- Every hub screen is a table in the window: grouped rows (ships and defences, research tiers with ★ keystones, law templates and enacted laws, finance holds and budgets, automation tiers and rules, ops vehicles, missions and alerts), status chips for blocking reasons, and Fe/Si/D cost columns. Production, finance, goals and legacy open with a metric strip; the market shows pairs as `Fe → Si` with rate, trend sparkline, change and the amount you get; diplomacy draws a standing gauge with tier chip and tribute; goals, daily and feats use progress bars; the star map colours its slot grid with a legend. Empty screens (intel, history, staff, ops, automation) explain what fills them. Times read as `1m 40s` instead of seconds, names are written out (`Light fighter`, `Extract iron`), the inspector lists costs as Fe/Si/D with shorter bars, and portraits only appear on the staff screen.

- Dispatch opens beside the star map at 120 columns and up instead of covering it: target and slot kind, a stepper per ship type with the owned count, flight time and fuel, and a warning when deuterium runs short. Smaller terminals keep the full-screen form.

- Overlays (story, away, victory, tactical, combat replay, invasion approval, advisor, activity, help, detail, history and spy reports) open as centred dialogs over the dimmed screen with their keys as keycaps in the footer. Story choices show number keycaps, the away summary groups deliveries, stalls and completions with Fe/Si/D gains and a duration, the replay draws both fleets as bars, and advisor tips read as callouts.

- The title screen uses the same navbar and status bar as play. At 90 columns and up the menu sits beside a save table (name, species, planets, fleet, last played, state) that marks the save Continue opens; an empty folder says New game starts one. Title help opens as a dialog.

### Fixed

- Nightly and release aarch64 `--version` smokes run qemu with the Ubuntu cross sysroot so the dynamic linker is found.

- Story, away, and spy overlays clear the screen underneath so numbered choices stay readable. Inline portraits are erased while an overlay is open.

### Added

- In-memory what-if scenarios: fork live state, queue intents, and fast-forward the copy with the same catch-up as play. Promote re-validates the action list against current live state through `propose`/`apply`. Hidden simulation stays off the outcome snapshot. Scenarios are not saved.

- `hoshi serve`: optional process that wraps one local save, takes the TUI/CLI lock, binds loopback by default, and answers `GET /healthz` with supported contract versions. Off unless started. Not a shared universe. See `docs/server.md`.

- `hoshi serve` `/v1` actions: `GET /v1/state`, `POST /v1/build`, `/v1/research`, `/v1/cancel`, and `/v1/fleet/send` call the same core actions as the CLI. Responses carry `schema_version` 2 (`docs/schema/serve-v1.json`). Fair-play: no hidden timers, RNG, unrevealed map, or `tick --advance`.

- `hoshi serve` `/v1` requires a bearer token scoped to that save (`HOSHI_SERVE_TOKEN` / `serve_token`, optional token file). Unauthenticated calls and tokens for another save return `unauthorized` (401). Per-token, per-action rate limits return `rate_limited` (429). `/healthz` stays open. Secrets stay out of the save. See `docs/server.md`.

- `hoshi serve` `GET /v1/events` is a WebSocket of build, research, fleet, and raid events. Reconnect with `?cursor=<id>` to replay missed rows. Unauthenticated sockets are refused. Same bearer as `/v1`. See `docs/server.md`.

- Shard player raids: a Chisei-hosted shard catches up both empires, then resolves against that snapshot with the same fleet combat as local play. Newbie protection and per-identity attack caps are enforced; plunder uses the defender share then cap. Local play is unchanged.

- Shard anti-cheat gate: a Chisei-hosted shard applies commands on its own clock (client timestamps ignored), rejects unsigned or altered bridge pulses, and rate-limits commands per identity. Local play is unchanged.

- Imperfect intel: remote facts carry source, observed time, age and confidence. Probe reports wait for light-time from the target, pick up range/sensor error, keep conflicting readings side by side, and a detected wave can be fed false counts. Intel screen, `hoshi intel` and `hoshi intel provenance` show that provenance. Fair-play: pending reports and the deceived flag stay off the CLI. Save schema v45.

- Predictive maintenance: asset condition from use, age and heat; time and usage plans; work orders with iron/silicon cost and downtime; bounded noisy telemetry; bathtub failure prediction on a documented horizon. Failures take assets offline and can open incidents. Maintenance screen in the Colony hub and `hoshi maintenance` / `schedule` / `complete` / `telemetry --export`. Save schema v44. See `crates/hoshi-core/data/maintenance.toml`.

- Incidents opened from raids, heat overflow, missed contracts and classification leaks, with leader assignment, resolution and post-incident reviews. A risk register reviews pirate activity, heat margins and the single home world daily. Incidents screen in the Empire hub and `hoshi incidents` / `open` / `assign` / `resolve` / `review`. Save schema v43. See `crates/hoshi-core/data/incidents.toml`.

- KPIs for output, energy, heat, budget variance, incidents, on-time missions and market profit. Targets belong to the empire, a colony or a role. Catch-up archives a daily report with variance and source events. KPI screen, cockpit widget, and `hoshi kpis` / `kpis set` / `kpis report` (JSON plus Markdown). Save schema v42. See `crates/hoshi-core/data/kpis.toml`.

- Treasury, department/fleet/colony budgets, forecast vs actual, and spending approvals. Construction, research and ships that would exceed a set limit wait in a queue until the player or owning leader approves. Credits value materials at the live market mid and energy at `energy_credit`; interest is simple per period on negative cash. Finance screen and `hoshi finance`. Save schema v41. See `crates/hoshi-core/data/finance.toml`.

- Event log, history and moon errors use Fe, Si, REE, H2O, He3 and D instead of M/C/D.

- TUI cost rows, resource bar and help use Fe, Si, REE, H2O, He3 and D (full names in help) with energy and heat beside the stockpiles.

- CLI JSON schema_version 2: `state` lists iron, silicon, rare earths, water ice, helium-3 and deuterium plus energy and heat. `metal` and `crystal` arguments error with the replacement id.

- Market mids follow L1 extraction energy (iron 1, silicon 1.5, deuterium 6). `hoshi simulate` reports per-material stock and rates; energy binds before any single material in the default early game.

- Construction stockpiles are iron, silicon, rare earths, water ice, helium-3 and deuterium fuel. Rocky worlds carry iron and rare earths, ice worlds water ice, gas giants helium-3. Old metal/crystal/deuterium saves migrate (schema v40): metal splits 95% iron / 5% rare earths; crystal becomes silicon; deuterium tankage stays fuel. See `docs/realism.md`.

- Automation as research progression: adaptive trade routes, multi-planet queues, then rule-based logistics (`keep metal on the capital`). Rules are data, conflict-checked, and evaluated on catch-up; control systems draw energy. The Automation screen dry-runs rules; `hoshi automation` adds, toggles and previews them. Save schema v39. See `crates/hoshi-core/data/automation.toml`.

- Release and install: the playable crate is named `hoshi` (`cargo install --git … --locked hoshi`). Version tags `vX.Y.Z` publish GitHub Release binaries for Linux (x86_64, aarch64), macOS (Intel and Apple Silicon) and Windows with `SHA256SUMS`, and the Homebrew tap formula is regenerated from the same tag. Release notes copy the changelog and state the save schema (v39; older saves migrate).

- Ubuntu packages: each release attaches `hoshi_X.Y.Z_amd64.deb` and `hoshi_X.Y.Z_arm64.deb` (Ubuntu 22.04+; Linux binaries now build on 22.04 for the glibc 2.35 floor). `curl -fsSL https://raw.githubusercontent.com/Sannrox/hoshi/main/scripts/install.sh | sh` picks the architecture, verifies `SHA256SUMS` and installs with `apt-get`.

- Nightly builds for alpha testers: `main` is built every night into a rolling `nightly` prerelease (Linux binaries, amd64/arm64 `.deb`, `SHA256SUMS`). Install or update with `HOSHI_CHANNEL=nightly` on the Ubuntu install script. `hoshi --version` shows the nightly stamp and commit; package versions `X.Y.Z~nightly.STAMP.SHA` sort before the `X.Y.Z` release.

- Self-play balance checks: `hoshi --self-play self-play --matrix pr|nightly` runs every species through the wonder, diplomacy and conquest strategies, prints win shares, time-to-victory and resource curves, and fails when a path drifts outside the casual band or one species pulls more than 25% ahead of the median. Off until `self_play = true` or `--self-play`. Pull requests run seed 1; the scheduled job runs the nightly seed list. Replay a flagged seed with `--seed N`. Sample path bots live in `examples/bots/`.

- Title screen when `hoshi` is launched without `--save`: Continue, New game, Load game, Settings, Credits and Quit. Continue shows a "While you were away" summary after a long gap. Save slots live in the user data directory; locked, newer-schema, corrupt and harness saves stay on the menu with a message. `--save PATH` still opens that file directly. `--continue` skips the menu and uses the documented exit codes when the slot cannot be played. Settings persist beside the saves (bridge and local AI stay off by default).
- Prestige reset: a completed wonder or a score threshold in `balance.toml` starts a new galaxy. Currency buys permanent bonuses (starter cache, mine and lab speed, extra queue slot) that survive the wipe. Per-run statistics stay in the save. The TUI prestige screen confirms what is kept and lost. `hoshi simulate` shows later runs producing more without skipping the first upgrade. Save schema v12.
- Pirate outposts on seeded galaxy slots. A fleet attack uses the existing combat resolver to strip orbital defences; troop transports then land. Invasion is refused while any defences remain. Ground combat is a seeded strength comparison and lands in the combat report. A win turns the outpost into a colony that counts against the colony cap. Rare-planet bonuses (production, extra fields, faster shipyard) come from `balance.toml` and show on the planet screen. Outpost strength scales with player combat points so early outposts stay winnable, and defences rebuild during catch-up if left alone. Troop transport is a new ship type. Save schema v11.
- Staged wonders in `balance.toml` (Dyson ring, stellar gate, observatory) with research prereqs. One wonder at a time; several planets can pay a stage. The timer runs during offline catch-up. Completed wonders feed `GameState::modifier`. The TUI wonder screen lists stage, remaining cost, and ETA at current income. Save schema v10 stores the job and completed ids.
- Scriptable JSON CLI (`hoshi state`, `build`, `research`, `cancel`, `fleet send`, `tick --advance`) on the same core actions as the TUI. Exit codes 0/2/3/4/5, versioned schema in `docs/schema/cli-v1.json`, deterministic `--seed` saves, and a save lock so the TUI and CLI cannot write together. See `docs/cli.md`. Save schema v9 stores the deterministic flag.
- Balance numbers load from a versioned `crates/hoshi-core/data/balance.toml` (embedded, validated). Override with `--balance PATH` or `HOSHI_BALANCE`. `hoshi simulate --days N` runs a greedy catch-up and prints a pacing report against documented targets (first upgrade within minutes, mine levels per day, bounded bridge metal ratio). See `docs/balance.md`.
- Multi-planet logistics: each colony has its own build queue that advances during offline catch-up. Transports move cargo between owned planets, limited by fleet capacity, with fuel paid at launch. Repeating routes fire on a schedule, skip and log when cargo or ships are short, and can be cancelled. Logistics research queues the same upgrade on several planets and reports the ones that cannot pay. The TUI `[`/`]` switcher shows each planet's resources and active build at a glance. Save schema v8 stores routes and mission cargo.
- Expeditions: send a fleet to the system's expedition slot for a chosen hold time. Outcomes (nothing, resources, ships, delay, early return, pirates, loss) come from a weighted table in balance config that scales with fleet size, astrophysics and hold time. The outcome seed is stored on the mission so reloading cannot re-roll it. A result line lands in the event log. Save schema v7.
- Bridge activity maps to bounded game effects: a merged PR pays a slice of production, green CI boosts mines for a while, a long agent run speeds research, red CI or a stuck agent can trigger a raid. Each mapping has a cooldown and a daily cap. Off unless the bridge is enabled. Save schema v6 stores boosts and limits.
- Optional GitHub poller on the local feed: merged pull requests and finished workflow runs via `gh api` (ETag, paginated lists) or a local webhook, deduplicated across restarts. Off unless the bridge is enabled and `github_repo` is set. No token is stored.
- Optional local agent activity feed: line-delimited JSON in the state directory (`feed.jsonl`) and an optional Unix socket. Unknown types are ignored; malformed and oversize lines are skipped. Reading resumes from a stored byte offset. Off unless the `bridge` cargo feature is on and config enables it. `hoshi post` appends a line. See `docs/bridge-events.md`.
- Colony ships and colonization research. An empty slot can be settled on arrival; occupied or over-cap landings send the ship home. Planet type and size come from the galaxy seed and the slot, survive save/load, and feed the same modifier lookup as research. Save schema v5 stores colonies and the colonize mission flag.
- Combat rapid-fire extra shots from `ships.toml`. `GameState::trigger_raid` is the shared raid API for the scheduler and a later bridge. The overview splits the combat report so both sides' losses are visible.
- Pirate raids: a countdown (default one hour) then a six-round fight against a pirate fleet scaled to the player. Shields refill each round; hull does not. A lost fight takes a capped share of stored resources. The combat report goes in the event log and the overview shows the countdown. Save schema v4 stores the next raid and the log.
- Fleets launch to `galaxy:system:position` with flight time from distance, slowest ship speed and a speed percent. Deuterium fuel is paid at launch. Missions run outbound, action and return phases during `catch_up`; recall mid-outbound returns in the elapsed time. Computer technology adds fleet slots. Save schema v3 stores missions.
- Nine ship types in `crates/hoshi-core/data/ships.toml` (fighters, cargos, cruiser, battleship, recycler, probe, explorer) with cost, time, combat stats, cargo, speed, fuel, shipyard level and research unlocks. `GameState::ship_stats` applies weapons, shields, armour and the ship's drive. Batches complete one ship at a time during `catch_up`. Counts persist in save schema v2. The TUI shipyard screen lists ships, requirements and the queue.
- Overview and planet screens in the TUI: resources with rates and caps, energy balance, build and research countdowns, a building list with queue management, and a research list. Tab switches screens; enter starts the selected item; unaffordable rows are dimmed with the missing amount. Quit still writes the save.
- SQLite save in the user data directory (`hoshi/save.sqlite`). Schema v1 stores resources, buildings, the build queue, research, timestamps and the RNG seed. Override the path with `--save` or `HOSHI_SAVE`. Writes run in one transaction and use WAL, so a crash mid-write keeps the previous save.
- Research tree loaded from `crates/hoshi-core/data/research.toml` (validated: unique ids, existing prereqs, no cycles). One research at a time; it completes during `catch_up` like buildings. Combat and fleet modifiers are applied through a single `GameState::modifier` lookup.
- Planet buildings and a 5-slot build queue in `hoshi-core`. Costs and durations come from `BalanceConfig`; robotics factory level shortens build time. Completions that fall in an offline gap apply in timestamp order and production is recomputed from each completion instant. Cancel refunds the paid cost in full.
- Resource model in `hoshi-core`: metal, crystal, deuterium and energy. Production, energy factor and storage caps come from `BalanceConfig`. `GameState::catch_up` resolves any offline gap in one call and is a no-op if the clock moves backwards.
- Workspace skeleton: `hoshi-core` (state, injectable clock, offline catch-up, SQLite save), `hoshi-tui` (status screen), `hoshi-bridge` (event type placeholder).
