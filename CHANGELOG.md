# Changelog

## Unreleased

### Fixed

- Story, away, and spy overlays clear the screen underneath so numbered choices stay readable. Inline portraits are erased while an overlay is open.

### Added

- Offline story authoring: `hoshi-author events draft --theme <theme> --count <n>` writes validated files to `content/drafts/` using the same loader as `story.toml`. Skeleton mode needs no model; an optional loopback `--endpoint` may polish the draft and is refused for public hosts. CI fails if a game crate references the drafts directory. The game never generates events at runtime. See `docs/authoring.md`.
- Title Settings → advisor model: toggle, endpoint, model name, LAN switch, and a non-blocking connection test. Values land in `config.toml`, never the save. Public hosts stay refused. Local rephrase still needs `--features advisor-model`.
- Optional local AI advisor: rule-based next-move suggestions from player-visible state. Off until Settings `ai_advisor`, `config.toml`, or `--advisor`. Overlay key `i`; `hoshi advise` prints JSON. Never acts. Optional `--features advisor-model` rephrases every suggestion in one HTTP request with a 100ms budget. Loopback only unless `advisor_allow_lan` is set for a private IPv4 URL; public hosts stay refused.
- Production screen: live chain rates, buffers, energy and heat, and the limiting factor (input, energy, heat, pollution, full storage, or transport delay) with a short rate history. Fits 80×24.
- Combat replay commentary from `commentary.toml` (twelve event types, template variants). Off by default; `commentary = true` in config or `--commentary`. Lines are chosen from the fight seed before playback so the overlay never waits on I/O. Optional `commentary-model` sends one loopback request with a 100ms budget and falls back to templates.
- First playable loop: `docs/playtest.md` checklist (launch, build, research, raid, offline return), `hoshi feedback` to append a local versioned note, and a Playtest feedback GitHub issue template.
- Guided first hour: a skippable opening plus contextual hints from `hints.toml` (mine finished, energy short, lab, storage, research, raid, fleet, shipyard). `g` jumps to the screen, `x` dismisses, `s` skips the rest. Progress is in the save (schema v26); Settings can hide hints or reset them.
- Moons form from battle debris around an owned planet (`[moons]`). Phalanx sensors list fleets in range; jump gates move parked fleets instantly between moons, with a cooldown and a refusal if the target has no gate. The planet switcher and galaxy map label moons. Save schema v25.
- Daily goals: three seeded picks per in-game day from `missions.toml`, with progress during catch-up, capped streak rewards in `[daily]`, a TUI daily screen, and `state` JSON. Save schema v24.
- Harness CLI end-to-end scenarios under `crates/hoshi-tui/tests/e2e`: build and research, catch-up across a restart, expedition plus raid, save lock, and old-schema migration. Goldens update with `HOSHI_UPDATE_GOLDEN=1 cargo test -p hoshi-tui --test e2e`.
- Title Prestige appears once a reset is available: unspent currency, owned bonuses, and a shop that buys with confirmation into the richest save. New game lists those bonuses and applies their starting extras to the new slot.
- New game shows a live galaxy preview for a pasted seed code (home type, size, outposts, generator). Checksum mismatches say so; blank still rolls a random seed. Load and the title menu copy the slot's shareable code with `y`. Saves from before galaxy seeds omit the code instead of showing seed 0.
- Title screen Achievements lists earned and locked rows from every save without taking the write lock. Hidden rows stay ??? until earned; measurable progress (colonies, fleet, prestige, raids, conquests, wonders) uses the best save. Totals cover playtime, battles, wonders, and galaxies finished by wonder or score, including prestige history.
- Title Settings has a keybindings page: list every remappable action by the screens that use it, press a new key to rebind, see conflicts without saving, and reset one action or all keys with confirmation. Changes land in `config.toml` and apply without a restart.
- Optional terminal notifications (off by default). Settings toggle plus `notify_*` keys in `config.toml`. A finished build, an incoming raid, or a returning fleet rings the bell and sends OSC 9/777; quiet hours skip them. Offline catch-up emits one summary instead of one line per event. Terminals that ignore OSC stay playable.
- Bridge activity status bar and a scrollable log (`a`) when the TUI is built with `--features bridge` and the bridge is enabled in config. Latest event, mine/lab boost countdowns, and the last 100 sourced effects; raids are marked. Off in a default build.
- Combat replays: each fight stores a seed plus round frames (save schema v23). The TUI overlay plays ASCII volleys at 10 fps from the overview (`r`) and the away summary; space pauses, `n` steps, `x` skips. Reduced motion and `no_animation` jump to the last frame. Fleet fights replay from the stored seed; layered planet battles and invasions replay from stored frames.
- TUI keymap is remappable in `config.toml` (`keys.quit = "p"`). Conflicting remaps are rejected and the defaults stay in force. `?` opens a help overlay that lists the actions for the current screen. Existing keys still work as before.
- Achievements from `achievements.toml` (twenty-four to start). Conditions evaluate during catch-up and award once. Hidden rows stay ??? until earned. Unlocks and dates survive prestige. The TUI achievements screen lists progress; an unlock lands in the event log. Save schema v22.
- ADR 0005: a shared universe is allowed only as a server-authoritative shard hosted on Chisei (Chisei clock, RNG and persistence; intents as governed Actions; on-demand catch-up; snapshot raids; bounded shards; players as tenants with markings). Partially supersedes ADR 0004; local play is unchanged.
- ADR 0004: hoshi stays a local single-player idle game. A shared universe is not in scope; the local save and client clock are not a multiplayer trust model.
- Branching technology tree: Industry, Military and Society each have a keystone; mutually exclusive choice nodes pick one path; Ancient techs stay hidden until a prestige run. The overview shows one branch at a time (`h`/`l`) with locked, available, in-progress, researched and excluded states. Existing research migrates. Save schema v21 stores exclusive picks. `hoshi simulate` reports keystone times against a 14-day galaxy target.
- ASCII galaxy map in the TUI: systems 1–81 with home, colonies, pirate outposts and fleets in flight (ETA). hjkl moves the cursor; Enter opens a dispatch overlay that launches through the existing fleet command.
- Empire laws as governed actions: propose, approve, enact and repeal through core and the CLI (`hoshi law propose|approve|repeal`). Catalog in `laws.toml` (emission cap, trade tariff, research priority, labour rules, metal levy). Effects apply on the effective date with optional phase-in; expected vs measured samples show on the TUI laws screen and in `state` JSON. Repeal restores prior parameters. Save schema v20.
- Industrial waste heat and pollution. Load is mine energy plus per-recipe extras in `balance.toml`; each planet type has a heat and pollution sink. Overflow slows work and adds pirate ships. Radiators, scrubbers, energy research (heat sink) and ecology research (pollution sink) restore capacity. The planet screen warns before overflow; `hoshi simulate` reports a heavy-industry snapshot that needs mitigation and stays viable with it.
- Commander, admiral, pirate and planet portraits in the TUI. ASCII is the layout-stable path; with images on, the same 8×8 grid becomes half-block cells, and terminals that advertise an inline graphics protocol receive the raw RGB after the frame. `--no-portraits` and a Settings toggle skip RGB. Moods follow event-log substrings in `moods.conf`. Assets and licenses live in `crates/hoshi-tui/ASSETS.md` (ADR 0003).
- Planet defences: light, heavy and ion cannons, missile silos, interceptors, a shield dome, orbital stations with hangar fighters, and garrison troops. They build through the existing shipyard queue. Raids against a defended planet run intercept, orbital, dome, battery and ground layers; empty grids keep the old fleet resolver so starter raids stay identical. Destroyed units roll a rebuild chance from `defences.toml`. Raid pirate strength includes defence combat points. Combat reports list each layer. Save schema v19.
- Spy probes: send `espionage_probe` ships to a pirate outpost. Report detail tiers, detection and per-probe destruction follow `[espionage]` in `balance.toml` (probes plus the espionage research gap). The same seed repeats the rolls. Reports store age and open from the TUI reports screen (the current galaxy-target list); `state` JSON attaches the latest report to each outpost for attack and invade. Save schema v18.
- Realism guidelines in `docs/realism.md`: physics and maths for production, energy, travel, orbits, heat, combat and prices; flavour stays fictional. Design Issues and `AGENTS.md` point at the file. Known gaps in the live config are listed there as follow-up.
- NPC factions and diplomacy: traders' guild, pirate clans and a dormant ancient empire in `crates/hoshi-core/data/factions.toml`. Standing moves with trades, raids, conquest and story choices, decays toward 0, and maps onto named tiers (market fee, raid delay, production modifiers). The TUI diplomacy screen shows standing, the next tier and a recent log; Enter pays pirate tribute. Save schema v17 stores standing and the log.
- NPC resource market: metal, crystal and deuterium trade at mean-reverting prices with fees, slippage and optional cargo for large lots. Story choices can shock a price. The TUI market screen shows mids, a sparkline and a trade preview. Catch-up ticks the walk. Save schema v16 stores prices and history.
- Story events from `crates/hoshi-core/data/story.toml` (twelve to start). A weighted pick offers one pending event after a delay and cooldown; the TUI overlay shows the text and numbered choices. Pending events survive save/load (schema v15). Ignored too long applies the event's default choice. Adding a row needs no code change.
- Shareable galaxy seeds: a short checksummed code (`XXXX-XXXX-XXXX-XX`) encodes the generator input. Same seed and generator version replay the same planets and outposts. `hoshi new --seed <code>` writes a live save. The overview shows the code; `y` copies it. Save schema v14 stores the generator version so older saves keep the galaxy they were created with.
- Production chains: mines extract planet deposits into recipes from `balance.toml` (ore through refined goods into frames, electronics and fuel). Rates are limited by inputs, energy and building levels, and stop when an input runs out. Deposits come from planet type and galaxy seed and show on the planet screen. Ship and building costs accept component names (`frames`, `electronics`, `fuel` / `propellant`). Existing metal, crystal and deuterium stockpiles stay the construction components. Save schema v13 stores intermediate goods.
- Title screen when `hoshi` is launched without `--save`: Continue, New game, Load game, Settings, Credits and Quit. Continue shows a "While you were away" summary after a long gap. Save slots live in the user data directory; locked, newer-schema, corrupt and harness saves stay on the menu with a message. `--save PATH` still opens that file directly. `--continue` skips the menu and uses the documented exit codes when the slot cannot be played. Settings persist beside the saves (bridge and local AI stay off by default).
- Prestige reset: a completed wonder or a score threshold in `balance.toml` starts a new galaxy. Currency buys permanent bonuses (starter cache, mine and lab speed, extra queue slot) that survive the wipe. Per-run statistics stay in the save. The TUI prestige screen confirms what is kept and lost. `hoshi simulate` shows later runs producing more without skipping the first upgrade. Save schema v12.
- Pirate outposts on seeded galaxy slots. A fleet attack uses the existing combat resolver to strip orbital defences; troop transports then land. Invasion is refused while any defences remain. Ground combat is a seeded strength comparison and lands in the combat report. A win turns the outpost into a colony that counts against the colony cap. Rare-planet bonuses (production, extra fields, faster shipyard) come from `balance.toml` and show on the planet screen. Outpost strength scales with player combat points so early outposts stay winnable, and defences rebuild during catch-up if left alone. Troop transport is a new ship type. Save schema v11.
- Staged wonders in `balance.toml` (Dyson ring, stellar gate, observatory) with research prereqs. One wonder at a time; several planets can pay a stage. The timer runs during offline catch-up. Completed wonders feed `GameState::modifier`. The TUI wonder screen lists stage, remaining cost, and ETA at current income. Save schema v10 stores the job and completed ids.
- Scriptable JSON CLI (`hoshi state`, `build`, `research`, `cancel`, `fleet send`, `tick --advance`) on the same core actions as the TUI. Exit codes 0/2/3/4/5, versioned schema in `docs/schema/cli-v1.json`, deterministic `--seed` saves, and a save lock so the TUI and CLI cannot write together. See `docs/cli.md`. Save schema v9 stores the deterministic flag.
- Balance numbers load from a versioned `crates/hoshi-core/data/balance.toml` (embedded, validated). Override with `--balance PATH` or `HOSHI_BALANCE`. `hoshi simulate --days N` runs a greedy catch-up and prints a pacing report against documented targets (first upgrade within minutes, mine levels per day, bounded bridge metal ratio). See `docs/balance.md`.
- Multi-planet logistics: each colony has its own build queue that advances during offline catch-up. Transports move cargo between owned planets, limited by fleet capacity, with fuel paid at launch. Repeating routes fire on a schedule, skip and log when cargo or ships are short, and can be cancelled. Logistics research queues the same upgrade on several planets and reports the ones that cannot pay. The TUI `[`/`]` switcher shows each planet's resources and active build at a glance. Save schema v8 stores routes and mission cargo.
- Expeditions: send a fleet to the system's expedition slot for a chosen hold time. Outcomes (nothing, resources, ships, delay, early return, pirates, loss) come from a weighted table in balance config that scales with fleet size, astrophysics and hold time. The outcome seed is stored on the mission so reloading cannot re-roll it. A result line lands in the event log. Save schema v7.
- Bridge activity maps to bounded game effects: a merged PR pays a slice of production, green CI boosts mines for a while, a long agent run speeds research, red CI or a stuck agent can trigger a raid. Each mapping has a cooldown and a daily cap. Off unless the bridge is enabled. Save schema v6 stores boosts and limits.
- Optional GitHub poller on the local feed: merged pull requests and finished workflow runs via `gh api` (ETag, paginated lists) or a local webhook, deduplicated across restarts. Off unless the bridge is enabled and `github_repo` is set. No token is stored.
- Optional local agent activity feed: line-delimited JSON in the state directory (`feed.jsonl`) and an optional Unix socket. Unknown types are ignored; malformed and oversize lines are skipped. Reading resumes from a stored byte offset. Off unless the `bridge` cargo feature is on and config enables it. `hoshi post` appends a line. See `docs/bridge-events.md`.
- Colony ships and colonization research. An empty slot can be settled on arrival; occupied or over-cap landings send the ship home. Planet type and size come from the galaxy seed and the slot, survive save/load, and feed the same modifier lookup as research. Save schema v5 stores colonies and the colonize mission flag.
- Combat rapid-fire extra shots from `ships.toml`. `GameState::trigger_raid` is the shared raid API for the scheduler and a later bridge. The overview splits the combat report so both sides' losses are visible.
- Pirate raids: a countdown (default one hour) then a six-round fight against a pirate fleet scaled to the player. Shields refill each round; hull does not. A lost fight takes a capped share of stored resources. The combat report goes in the event log and the overview shows the countdown. Save schema v4 stores the next raid and the log.
- Fleets launch to `galaxy:system:position` with flight time from distance, slowest ship speed and a speed percent. Deuterium fuel is paid at launch. Missions run outbound, action and return phases during `catch_up`; recall mid-outbound returns in the elapsed time. Computer technology adds fleet slots. Save schema v3 stores missions.
- Nine ship types in `crates/hoshi-core/data/ships.toml` (fighters, cargos, cruiser, battleship, recycler, probe, explorer) with cost, time, combat stats, cargo, speed, fuel, shipyard level and research unlocks. `GameState::ship_stats` applies weapons, shields, armour and the ship's drive. Batches complete one ship at a time during `catch_up`. Counts persist in save schema v2. The TUI shipyard screen lists ships, requirements and the queue.
- Overview and planet screens in the TUI: resources with rates and caps, energy balance, build and research countdowns, a building list with queue management, and a research list. Tab switches screens; enter starts the selected item; unaffordable rows are dimmed with the missing amount. Quit still writes the save.
- SQLite save in the user data directory (`hoshi/save.sqlite`). Schema v1 stores resources, buildings, the build queue, research, timestamps and the RNG seed. Override the path with `--save` or `HOSHI_SAVE`. Writes run in one transaction and use WAL, so a crash mid-write keeps the previous save.
- Research tree loaded from `crates/hoshi-core/data/research.toml` (validated: unique ids, existing prereqs, no cycles). One research at a time; it completes during `catch_up` like buildings. Combat and fleet modifiers are applied through a single `GameState::modifier` lookup.
- Planet buildings and a 5-slot build queue in `hoshi-core`. Costs and durations come from `BalanceConfig`; robotics factory level shortens build time. Completions that fall in an offline gap apply in timestamp order and production is recomputed from each completion instant. Cancel refunds the paid cost in full.
- Resource model in `hoshi-core`: metal, crystal, deuterium and energy. Production, energy factor and storage caps come from `BalanceConfig`. `GameState::catch_up` resolves any offline gap in one call and is a no-op if the clock moves backwards.
- Workspace skeleton: `hoshi-core` (state, injectable clock, offline catch-up, SQLite save), `hoshi-tui` (status screen), `hoshi-bridge` (event type placeholder).
- ADR 0001 and ADR 0002.
